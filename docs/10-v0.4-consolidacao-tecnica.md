# Test Quest v0.4 — Consolidação Técnica

## Objetivo

A v0.4 fortalece a base interna do Test Quest sem alterar a experiência concluída na v0.3.0.

O foco é:

- persistência confiável;
- migração segura;
- recuperação de dados incompatíveis;
- redução gradual do controlador principal;
- testes que permitam novas funcionalidades sem regressões.

## Estratégia de desenvolvimento

A refatoração será incremental:

```text
Base funcional da v0.3
→ persistência versionada
→ serviços extraídos
→ testes de fluxo
→ remoção controlada do legado
```

Não serão reescritas várias áreas simultaneamente.

# Etapa 1 — Persistência versionada

## Estado da sessão

Esquema atual:

```js
{
  schemaVersion: 3,
  versao: 3,
  id,
  status,
  listaNome,
  questoes,
  atual,
  respostas,
  anotacoes,
  temposMs,
  revisao,
  marcacoesAlternativas,
  temporizadorPausado,
  opcoes,
  importadoEm,
  iniciadoEm,
  finalizadoEm
}
```

A propriedade `versao` é mantida temporariamente para compatibilidade com arquivos exportados anteriormente.

## Chaves atuais

```text
testQuest.state
testQuest.settings
testQuest.history
```

## Chaves legadas reconhecidas

```text
resolvedorQuestoesV2.estado
resolvedorQuestoesV2.config
```

## Fluxo de migração

1. procurar a chave atual;
2. validar o JSON;
3. normalizar o esquema;
4. se a chave atual não existir, procurar a legada;
5. salvar uma cópia limitada no backup de migração;
6. gravar o estado normalizado na chave atual;
7. remover a chave legada somente após a gravação atual ser concluída;
8. informar o usuário quando uma sessão tiver sido migrada ou reparada.

## Dados incompatíveis

Cargas inválidas não são usadas diretamente pela interface.

Elas são armazenadas, quando possível, em:

```text
testQuest.invalidDataBackup
```

O backup mantém no máximo cinco entradas, evitando crescimento indefinido.

## Validações aplicadas

- sessão precisa possuir questões;
- categorias aceitas: objetiva e discursiva;
- IDs ausentes ou duplicados são substituídos;
- alternativas objetivas precisam conter A–E;
- gabarito objetivo precisa ser A–E;
- índice atual é limitado à lista existente;
- respostas e mapas órfãos são descartados;
- tempos negativos ou inválidos tornam-se zero;
- marcadores inválidos são removidos;
- datas inválidas tornam-se nulas;
- opções ausentes recebem valores padrão.

# Configurações

Esquema atual:

```js
{
  schemaVersion: 1,
  tema: "light" | "dark",
  efeitosVisuais: "system" | "full" | "reduced"
}
```

A preferência de efeitos visuais foi reservada para a v0.5. Durante a v0.4, o comportamento continua seguindo o sistema operacional.

---

# Histórico

O histórico passou ao esquema 2.

Durante a leitura:

- entradas inválidas são descartadas;
- sessões com o mesmo ID são deduplicadas;
- a versão concluída mais recente é preservada;
- números negativos são normalizados;
- desempenho sem questões objetivas permanece `null`.
